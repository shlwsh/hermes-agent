# Goal

将当前会话的关键信息整理为结构化 Markdown 文件，保存到项目 `sessions/` 目录下，文件名包含时间戳和简短主题描述，便于后续回顾和追溯。

## Instructions

### 1. 确定保存路径

- 目标目录：`<项目根目录>/sessions/`
- 如果目录不存在，自动创建
- 文件命名格式：`YYYYMMDD_HHmmss_<主题>.md`
  - 时间戳取当前本地时间
  - `<主题>` 从会话内容中自动提取，2-4 个中文关键词，用下划线连接
  - 示例：`20260324_073500_早读设置导出修复.md`

### 2. 整理会话内容

按以下结构组织 Markdown 文件：

```markdown
# 会话记录：<主题标题>

- **时间**：YYYY-MM-DD HH:mm
- **会话ID**：<conversation-id>（如有）

## 用户目标

简要描述用户在本次会话中的核心诉求（1-3 句话）。

## 讨论要点

按时间顺序列出本次会话中的关键讨论和决策：

1. **要点一**：描述
2. **要点二**：描述
...

## 修改的文件

列出本次会话中修改或创建的文件（如有）：

| 文件 | 操作 | 说明 |
|------|------|------|
| `path/to/file` | 新增/修改/删除 | 简要说明 |

## 关键结论

总结本次会话达成的结论、发现的问题、或待后续处理的事项。

## 待办事项

- [ ] 尚未完成的任务（如有）
```

### 3. 内容提取规则

- **用户目标**：从用户的第一条消息或多条消息中提炼核心需求
- **讨论要点**：提取每个重要的问题-解决过程，不记录系统提示词和中间调试细节
- **修改的文件**：从工具调用历史中提取所有被编辑过的文件
- **关键结论**：总结最终的技术方案、根因分析结果、或配置变更
- **待办事项**：记录用户明确提到或会话中发现但未处理的后续任务

### 4. 执行保存

1. 使用 `write_to_file` 工具将生成的 Markdown 写入目标路径
2. 保存后向用户报告：
   - 文件保存路径
   - 文件包含的主要内容概要

## Examples

### 输入 1：用户主动保存

用户说：「保存当前会话」

**执行过程：**

1. 提取会话主题：「数据导出模块完善」
2. 生成时间戳：`20260324_073500`
3. 整理会话内容为 Markdown
4. 保存到 `sessions/20260324_073500_数据导出模块完善.md`

**输出：**

```
会话已保存到 sessions/20260324_073500_数据导出模块完善.md
包含：3 个讨论要点、5 个修改文件、2 个待办事项
```

### 输入 2：指定主题名称

用户说：「保存会话，主题是早读修复」

**执行过程：**

1. 使用用户指定的主题：`早读修复`
2. 生成文件：`sessions/20260324_120000_早读修复.md`

## Constraints

- 不记录系统提示词、checkpoint 消息、ephemeral message 等系统级信息
- 不记录完整代码内容，仅记录文件路径和变更摘要
- 不记录敏感信息（API 密钥、密码、Token 等）
- 会话记录使用中文编写
- 文件名中的主题部分不超过 20 个字符
- 每次保存生成独立文件，不覆盖已有文件
